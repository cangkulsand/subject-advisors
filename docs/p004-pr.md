# P004 delivery summary — initial main baseline

The user designated the working P004 implementation as the repository's initial main
branch so the team can clone it and build their assigned modules from a common base.
This delivery is published directly as that initial baseline rather than as a feature
PR against an empty repository. Future changes use feature branches and PRs to main.

## Delivered behavior

Clerk signup/login/logout, verified primary institutional email policy, server-side
session/role/access checks, idempotent Neon account association, the access migration,
GET /api/me and bodyless POST /api/me/initialize, and a runnable Vite/Wrangler auth preview.
Empty Worker POST streams are accepted while nonempty account payloads remain rejected.

## Validation

Fresh npm ci, typecheck, lint, 47 unit tests, module/Vite builds and 11 mocked browser
checks passed. Five live Neon tests and ten real HTTP regressions passed separately.
The user reported manual signup/domain, logout/sign-in, role denial and account reuse
checks passed. Human peer review remains pending.

## Team starting point

README.md and CONTRIBUTING.md describe cloning main, local development settings,
owner-specific feature branches and PRs. Shared sprint/process/theme documents are
included for the other programmers.

Auth integration contracts are in p004-auth-handoff.md. P001 must implement ProfileReader
and profile setup; FOUNDATION integrates the shared app/API/catalogue/tooling. Other
owners retain their own feature scope. The local p002 folder was not included.
