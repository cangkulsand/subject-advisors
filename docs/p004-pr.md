# P004 Sprint 1: Clerk registration, sessions and access control

Clerk registration and login now bind verified institutional students to a unique
local access assignment. The Worker validates session status, current email policy,
role and suspension on private requests. New students are directed to profile setup;
the setup form remains a P001 integration dependency.

Includes the P004 access migration, GET /api/me, bodyless POST /api/me/initialize,
reusable auth middleware, React signup/login/logout components and an isolated
Vite/Wrangler local preview. Empty HTTP POST streams are accepted while actual
initialization payloads remain rejected.

## Validation

- Automated: 47 unit tests; 10 actual HTTP body regressions; typecheck, lint and auth
  module build passed. Five live Neon schema/constraint tests passed separately.
- Browser automation: 11 checks with explicitly mocked Clerk/API.
- User-reported manual checks: institutional/domain behavior, logout/sign-in,
  privileged-page denial and idempotent STUDENT/ACTIVE account binding passed.
- Live configuration: Clerk development credentials verified; migration applied to
  the configured Neon database. No real identities or secrets are included in source.

## Shared impact and dependencies

Root package/config files provide only a temporary P004 validation/local-preview
harness. Merge them with FOUNDATION's tooling. P001 must implement ProfileReader and
